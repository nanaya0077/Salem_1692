# 原型笔记 · 传染阶段（#59）

**问题**：390×844 上，传染阶段的两步选择、提交后等待、20 秒倒计时与换牌过场，应该用哪种界面形态？现有 motion/audio 事件形状够不够？

这是 `#59` 的 throwaway 原型；生产代码在 `apps/web/`，不要把这个页面的实现直接搬过去。

## 运行

```bash
cd prototype
python -m http.server 8099
# http://127.0.0.1:8099/conspiracy.html
```

- `?variant=sheet|ritual|inline`：三种界面；底部也可切换，键盘 ←/→ 循环。
- `?count=4|9|12`：人数；4/9 人每人 5 张身份卡，12 人每人 3 张。
- 底部「状态」：展开当前 projection 与事件表；用来核对零泄漏与 motion 输入。

## 三种形态（结构不同，不是换皮）

| variant | 结构 | 主要取舍 |
|---|---|---|
| `sheet` 抽屉 | 牌桌压暗，底部抽屉承载选择；候选是 3–5 张大卡 | 保留牌桌上下文；抽屉占约 45% 高度 |
| `ritual` 仪式 | 全屏暗红，12 席环形，中央扇形候选，CTA 固定在底部 | 气氛最强；12 人时席位只能压到 9px，中央 CTA 已移到底部 |
| `inline` 原位 | 不遮挡牌桌，左邻席位高亮，候选是席位上的编号 chip，底部浮动条 | 最快；等待态不如前两者显眼 |

## 原型内已模拟的流程

1. 抽到者（你）进入第 1 步：从黑猫持有者（威廉）的未揭示身份卡里选一张。
2. 提交后进入等待/结算，再进入第 2 步：全体存活玩家同时从自己的左邻取一张。
3. 机器人陆续提交，显示聚合「已提交 n/m」；你提交后收齐即结算。
4. 换牌过场：左邻 → 你，1.4 秒；按到达顺序追加到你的身份卡行。
5. 结算后只有你能点开新牌看类型；位置对其他人可见，牌面不下发。
6. 20 秒归零自动取第一张，显示兜底提示。

## 初步结论（待仓主选形态）

- **可读性**：`sheet` 在 4/9/12 人都能放下 3–5 张候选；4 人时 4 席单行（已修 `.seatrow.c4`），9 人 3×3，12 人 3×4；拇指点击区最稳。`ritual` 12 人环形能放下（席位 9px），候选在中央，但环形与候选之间留白多，视线移动大。`inline` 12 人席位 3×4，候选 chip 在下方仍可见，但 chip 点击目标最小。
- **等待态**：`sheet` 的抽屉底部一行「已提交 · 等待其他玩家 n/m」最清楚；`inline` 的浮动条次之；`ritual` 的底部 CTA 区可以承载，但视线要离开中央。
- **换牌过场**：三种形态共用同一段「左邻 → 你」的飞牌；1.4 秒在 390 宽上不拖沓。`ritual` 的仪式感最强，但 12 人时建议只作为第 1 步的可选演出或降级为 `sheet`。
- **倾向**：生产形态优先 `sheet`（#57 的主路径）；`ritual` 可作为「首次传染/第 1 步」的强化演出，并保留跳过；`inline` 作为低动效/快速模式。

## motion / audio 接口核对

现有事件表够用，不需要改服务端协议：

- `conspiracyStarted { drawerId }` → 进入阶段/第 1 步转场。
- `trialRevealed { playerId, kind, cause: "conspiracy", chooserId }` → 翻牌落位；`kind` 只在公开揭示时下发。
- `conspiracySwap { fromId, toId }` → 每对一张的飞牌；按事件顺序串行播放即可。
- 阶段结束没有单独事件；以投影 `phase` 从 `conspiracy` 回到 `action` 作为收尾信号即可。若 motion 需要一条总时长，再考虑加 `conspiracySettled { swaps }`（可选，不是本期必需）。

需要在 `apps/web/motion-events.js` 新增三组映射：`conspiracyStarted`、`trialRevealed(cause=conspiracy)`、`conspiracySwap`。`apps/web/audio.js` 建议新增 `conspiracy_start` / `conspiracy_pick` / `conspiracy_swap` 三个 sfx id；无音效时静默降级。

## 已知简化

- 不接服务端；机器人按固定延迟提交；不做断线重连。
- 身份卡类型是演示数据；玛丽持黑猫、左邻无未揭示等边界没有在原型里演。
- 没有真实音效/震动；只用 CSS 过场验证节奏。
- 不是最终视觉；卡面与牌桌都是占位。
